# 测试、Bug 修复与重构规范

本文件在任务涉及单元测试、Bug 修复、回归验证或重构时按需读取。

## 优先测试的代码

以下代码通常具有较高测试价值：

- 纯算法。
- utils。
- parser / converter。
- 状态机。
- 插件逻辑。
- 定位计算。
- 边界判断。
- Bug 修复对应的回归路径。

## 测试覆盖维度

根据任务选择必要维度：

```text
正常情况
边界情况
异常情况
空值
极值
状态切换
回归场景
```

不要机械为每个函数创建低价值测试；测试应保护真实行为和关键边界。

## Bug 修复流程

```text
复现问题
  ↓
定位真正 Root Cause
  ↓
确认影响范围
  ↓
设计最小修改
  ↓
实现修复
  ↓
增加回归测试
  ↓
执行项目实际质量检查
```

禁止通过删除失败测试、扩大忽略规则、添加无关延迟或绕过类型检查来“修复”问题。

## 重构

重构默认保持外部行为不变。

重构前应确认：

- 当前行为和 API。
- 现有测试覆盖。
- 依赖关系。
- 需要改善的真实问题。

重构后应重点确认：

- 公共 API 是否保持兼容。
- 是否产生循环依赖。
- 是否引入新的不必要抽象。
- 行为测试是否仍然通过。

## 工程质量检查

不要在 Skill 中硬编码命令。应读取当前项目的：

- `AGENTS.md`
- `package.json`
- workspace scripts
- CI 配置
- 现有开发文档

按实际项目执行必要的 Format、Lint、Type Check、Unit Test 和 Build。

若环境无法执行某项检查，应在最终说明中明确“未执行”及原因，不能写成“已通过”。
